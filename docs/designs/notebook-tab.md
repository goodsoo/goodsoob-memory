## Problem Statement

캡틴이 studio 사업화 파트장이 되면서 배경지식이 없는 분야(데이터 사업, UI/UX, PM, 미팅 말하기 등)를 주제 단위로 계속 공부해야 한다. 자료 조사는 채팅에서 Claude 에게 맡긴다. 그런데 조사 결과는 brain 에 md 로 쌓일 뿐이고, 그걸 **NotebookLM 처럼 소화하는 자리**가 없다. brain 을 그대로 보는 건 노트북의 목적이 아니다. 목적은 소화(형식 변환 + 근거 확인 + 기억)다.

## What Makes This Cool

- **검증 범위가 명시된 인용.** NotebookLM 의 인용도 엉뚱한 자료를 가리킬 수 있다는 사용자 보고가 있다. 이 탭은 인용마다 원문 발췌를 들고 있고, 렌더할 때 그 발췌가 노트북의 자료 파일에 실제로 있는지 **문자열로 대조**한다. 불일치는 빨간색.
  - **보증하는 것:** 소화물의 발췌가 노트북 자료 파일(`sources/` 등)에 글자 그대로 존재한다. 즉 소화 단계에서 지어낸 인용은 잡힌다.
  - **보증하지 않는 것 (명시):** ① `sources/` 파일 자체가 웹 원문과 일치하는지(그 파일도 조사 모드의 Claude 가 쓴다). ② 발췌가 그 주장을 실제로 뒷받침하는지(관련성).
  - **완화:** 조사 모드는 발췌를 가져온 페이지 텍스트에서 그대로 복사하고 URL 을 남겨 캡틴이 표본 확인할 수 있다. 칩은 발췌 원문을 그대로 보여줘 뒷받침 여부는 읽는 사람이 판단한다. 이 한계는 탭 UI 문구에도 적는다.
- **"모르는 것"이 다음 할 일이 된다.** 자료에 없는 건 지어내지 않고 "조사 필요"로 남기고, 그 목록이 다음 채팅 조사 요청이 된다.
- 자료 / 내 판단 / AI 해석이 눈으로 구분된다.

## Constraints

- Builder 모드, 1인용. 공유 · 멀티유저 · 과설계 금지.
- 앱에 조사 기능 없음 (캡틴: "굳이 자료 찾아주는 역할을 앱에 기능으로 만들지 말고, 내가 채팅으로 요청할게").
- 회사에서 쓰므로 녹음 · 음성 답변 같은 상호작용은 불가 (캡틴: "회사에서 그런 걸 하기엔 힘들어").
- 탭 실행 중 AI 호출 없음. 생성은 전부 채팅(Claude)에서.
- 앱 경계(`docs/designs/work-brain-workbench.md`): 문서 읽기 + 리치 렌더 = memory 홈. 노트북 탭은 검색 기능이 없으므로 tower 의 "gbrain 검색" 역할과 겹치지 않는다.

## Premises (합의됨)

1. 노트북 = brain 안 아무 폴더. 허브 `README.md` frontmatter `type: notebook` 으로 식별 (RESOLVER 도메인 배치 유지).
2. 조사는 채팅에서 Claude 가 한다. 앱은 조사하지 않는다.
3. 탭의 가치는 brain 열람이 아니라 소화(형식 변환 · 근거 확인 · 기억).
4. 탭은 Claude 가 만든 소화물을 렌더만 한다.
5. 재료(README · topics · sources · interviews · glossary)는 brain md 로 git · 검색 대상. 순수 파생물은 노트북 안 `_digest/` 에 두고 `**/_digest/` 를 brain `.gitignore` 에 추가 (git · 검색 제외, iCloud 동기화만. 선례 `_audio/*`, `_archive/*`). `_` 접두사라 메모장 노트 트리에서도 빠진다 (`src/lib/vault/scan.ts:99` `isNonNotePath`).
6. 조사(웹 가능) → `sources/` 에 URL · 날짜 · 발췌로 저장 → 소화(노트북 자료만)로 단계를 끊는다. 모든 주장은 `{파일, 원문 발췌}` 인용을 갖고 자료 / 내 판단 / AI 해석을 구분한다. 자료에 없으면 "조사 필요". 탭은 발췌를 원문과 대조해 실패를 표시한다.

## Approaches Considered

- **A. 브리핑 + 인용 검증만.** 가장 빠르지만 읽기만으로는 처음 배우는 내용이 남지 않음. 퀴즈를 더해 채택안으로 확장.
- **B. 전 형식(마인드맵 · 오디오 · 퀴즈 · 플래시카드).** TTS 선택(macOS `say` 저품질 vs 클라우드 비용 · 외부 전송)과 상태 설계가 붙어 스터디 시작이 늦어짐. 다음 단계로 미룸.
- **C. 미팅 리허설(녹음으로 답하고 Claude 채점).** 회사에서 음성 답변이 불가해 기각.
- **주관식 퀴즈.** 자가 채점이든 Claude 채점이든 객관식 대비 얻는 게 적어 기각 (캡틴: "주관식을 만들지 말자 그럼").

## Recommended Approach — 브리핑 + 인용 검증 + 객관식 퀴즈

### 파일 계약

```
<notebook>/
  README.md        type: notebook. 허브 + 브리핑(결론 섹션)   [git · 검색 O]
  topics/ sources/ interviews/ glossary.md                   [git · 검색 O]
  _digest/                                                    [gitignore]
    quiz.json            (탭은 읽기만 한다. 노트북 탭은 brain 에 아무것도 쓰지 않는다)
```

- **브리핑 = README 의 `## 지금까지의 결론` 섹션**(기존 studio-biz README 의 제목 그대로). 범위는 그 제목부터 다음 H2 직전까지. md 유지 → 검색에 잡힘. 인용은 GFM 각주로: 본문 `문장[^3]`, 정의 `[^3]: sources/03-xxx.md "원문 발췌"`. 탭이 각주를 파싱해 칩으로 렌더하고 발췌를 대조한다.
- **주장 단위와 종류**: 단위는 브리핑 섹션의 불릿 1개(불릿이 아니면 문단 1개). 단위마다 다음 중 하나여야 한다.
  - 각주 1개 이상 → 자료 주장
  - `(내 판단)` 또는 `(AI 해석)` 접두 마커 → 해당 스타일 (각주 없어도 됨)
  - 둘 다 없음 → 탭은 회색 "근거 없음" 라벨로 표시(자료로 보이지 않게), 검증 CLI 는 실패 처리.
- **조사 필요**: README `## 조사 필요` 섹션(다음 H2 직전까지)의 불릿 목록.
- **quiz.json**: `{ generated_at, questions: [{ id, q, choices: [4], answer: <index>, explanation, cites: [{ src, quote }] }] }`
- **문항 id**: `q-YYYYMMDD-NN`. 렌더 key 와 채팅에서 문항을 가리키는 용도(예: "q-20261112-03 이상해")일 뿐, 진도 저장에 쓰지 않는다.
- **퀴즈는 읽기 전용 (eng review 결정, 2026-11-12)**: 진도 · 오답 기록을 저장하지 않는다. 회차는 매번 처음부터, 끝나면 맞은 개수만 표시. 시작할 때마다 **문항 순서와 보기 순서를 섞는다**(보기를 섞을 때 `answer` 인덱스도 같이 옮김). 이유: 기록 저장은 쓰기 경로 · id 안정 규칙 · iCloud 충돌 · 출제 순서 로직을 끌고 오고, 쓸 때마다 서버가 brain 전체를 커밋한다(아래 NOT in scope).
- **읽기 경로 (코드 확인)**: 기존 `/api/vault/read` (`server/index.ts:254`) 는 확장자 · `_` 접두와 무관하게 vault 상대 경로를 받는다. 경로 가드는 `server/vaultCore.ts` 의 세그먼트 단위 `..` 차단. `isNonNotePath` 는 노트 목록 스캔 필터일 뿐 read 를 막지 않는다. 새 엔드포인트 불필요.

### 탭 화면

- 노트북 목록: brain 전체에서 `type: notebook` README 수집 (기존 vault scan 재사용).
- 노트북 상세 = 브리핑 / 퀴즈 / 조사 필요 3 구역.
- 인용 칩 클릭 → 원문 파일을 열고 발췌 구간 하이라이트. 발췌 불일치 칩은 빨간색 + "원문에서 못 찾음".
- 퀴즈: 시작 시 문항 · 보기 셔플 → 보기 클릭 → 즉시 정오 + 해설 + 근거 칩. 회차 끝에 맞은 수. 저장 없음.

### 생성 계약 (채팅 쪽, `/study` 스킬로 고정)

- 조사 모드: 웹 검색 → `sources/NN-*.md` (URL · 날짜 · 고른 이유 · 핵심 발췌). 소화물에 바로 쓰지 않는다.
- 소화 모드: 노트북 폴더 자료만 읽고 README 결론 · 조사 필요 · `quiz.json` 갱신. 외부 지식 금지, 발췌는 원문 그대로 복사.
- 생성 직후 **검증 CLI** 로 자체 검사해 불일치 · 근거 없음 0 으로 넘긴다 (탭 검증은 2차 방어). CLI 는 앱과 같은 순수 함수(각주 파서 · `verifyQuote` · 주장 단위 검사)를 import 하는 `scripts/verify-notebook.ts` 이고, 스킬은 `bun scripts/verify-notebook.ts <노트북 경로>` 로 돌린다. 로직이 한 곳이라 두 검사가 갈라지지 않는다.
