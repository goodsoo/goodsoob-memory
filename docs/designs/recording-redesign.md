# Design: 녹음 탭 개편 — 흐름 기준 재구성 · 교정 후 연결 · 화자별 턴 화면

상태: 초안 (2026-11-02, 캡틴 대화로 결정 확정)
선행: `docs/designs/recording-tab.md` (PR1 #116, PR2 #117). 이 문서가 그 문서의 **행선지·연결 후 교정·메모 쪽 음성 기록 탭·PR3** 부분을 대체한다. 서버 job(화자분리·교정 후보)과 이사(link) 메커니즘은 그대로 쓴다.

## 문제

PR1·PR2 로 기능은 붙었지만 녹음 상세 화면에 헤더·플레이어·전사 처리 폼·행선지 패널(검색·후보 두 묶음·연결 버튼)·전사 미리보기가 같은 무게로 세로로 쌓였다. 화면이 어디부터 보라고 말해주지 않는다. 사이드바 행은 전부 "10월 29일 오후 5:52 · 초벌 전사" 꼴이라 열어보기 전엔 무슨 녹음인지 모른다. 버릴 방법이 없어 1~26초 테스트 녹음이 42개 목록을 채운다. 그리고 초벌 전사 상태에서 바로 연결할 수 있어, whisper 원문이 메모로 들어간 뒤엔 녹음 화면에서 고칠 길이 없다(연결 = 전사 이사, 녹음 쪽엔 텍스트가 남지 않음).

## 유저 흐름 (이 화면의 척추)

녹음 탭 = 회의 뒤 쌓인 녹음을 하나씩 비우는 **인박스이자 작업대**.

들어오면 처리할 녹음 맨 위가 열려 있음 → 첫 문장·▶ 로 무슨 녹음인지 확인 → 버릴 거면 **삭제**(자동으로 다음) → 남길 거면 **인원·이름** → **화자분리** → (선택) **Claude 교정 후보** → 턴 화면에서 **듣고 고치기** → **교정 완료** → **메모에 연결**(주의사항 확인) → 자동으로 다음 녹음.

화자분리·교정 후보는 오래 걸리므로 기다리지 않고 다른 녹음으로 넘어갈 수 있다. 진행 상태는 사이드바 행에 작게.

## 결정 (2026-11-02)

- **D-R1 교정 완료 전엔 연결 금지.** 연결은 파이프라인이 "교정본"일 때만 열린다. 연결하면 전사가 메모로 이사하고 녹음 화면에선 더 고칠 수 없으므로, 메모에는 항상 최종본만 들어간다. 이로써 `recording-tab.md` 의 "초벌 전사에서 바로 행선지"(raw-promoted 승격)와 "연결 후 교정"(섹션 해시·덮어쓰기 확인 모달)은 **폐기**.
- **D-R2 연결 확인에 주의사항 필수.** 확인 단계 문구: "이 메모에 연결합니다. 연결하면 전사본이 메모의 음성 기록으로 옮겨지고, 녹음 화면에서는 더 이상 전사를 고칠 수 없습니다." [연결] [취소].
- **D-R3 '전사만 보관' 제거.** 보관한 전사는 brain 색인·git 밖(`_audio`)이라 녹음 탭 안에서만 보이는 막다른 곳이었다. 남길 건 "새 메모로", 버릴 건 "삭제". archive/unarchive API·`archived` 마커·"보관됨" 그룹 제거. 남아 있는 `archived` 마커는 무시(미정 취급).
- **D-R4 녹음 삭제.** `_audio/<base>.m4a` + `_audio/<base>.txt` + `.stt/<base>/` 를 macOS 휴지통(`~/.Trash/goodsoob-녹음/<base>-<stamp>/`)으로 이동. Finder 에서 복구 가능, iCloud brain 용량에서 빠짐. 연결된 녹음은 오디오·`.stt` 만 지우고 메모 전사는 그대로(메모 쪽 ▶ 는 "녹음 파일 없음"). `.stt/imported-voicememos.txt` 는 파일이라 건드리지 않음 → auto_stt 재수입 없음. 사이드바 다중 선택 삭제 지원.
- **D-R5 옛 교정본은 예외 없음.** 옛 `/transcribe` 교정본(`_audio/<base>.txt`, 12개)은 이미 파이프라인 "교정본"이라 원할 때 바로 연결. 따로 처리하지 않는다.
- **D-R6 화자별 턴 화면 = 공용 컴포넌트 하나.** 녹음 탭과 메모의 음성 기록 탭이 같은 컴포넌트를 쓰고 **둘 다 편집 가능**. 차이는 읽고 쓰는 곳뿐(녹음 탭 = 연결 전 작업 파일, 메모 탭 = 사이드카 + 기존 undo history). 메모 탭의 파일 업로드(이어붙이기)는 유지.
- **D-R7 리뷰는 턴 화면 위 하이라이트.** 별도 리뷰 패널(옛 PR3 `ReviewPanel`) 대신, Claude 교정 후보를 해당 턴의 해당 구절에 하이라이트로 얹고 그 자리에서 수락·원문 유지·직접 고침. `apply_decisions.py` 는 쓰지 않는다(턴 화면이 작업 파일을 직접 고친다).
- **D-R8 Claude 교정 후보는 선택.** 화자분리 후 직접 고치고 바로 "교정 완료"를 눌러도 된다. 후보는 고칠 곳을 찾아주는 도우미.
- **D-R9 로컬 LLM 엔진은 이번엔 뺀다.** 개인정보가 많은 녹음은 외부 전송 없이 교정하고 싶다는 요구가 있어 실측했다(2026-11-02, 5분 녹음 1개, 같은 `corrections_prompt.md`). Claude 31초·후보 22개(A 3개 전부 타당) / EXAONE 3.5 7.8b 26초·3개(겹침 0) / qwen2.5 14b 50초·3개 / EXAONE 3.5 32b 163초·11개(겹침 7, 틀린 확신·규칙 위반 섞임). 로컬은 찾는 양이 절반 이하이고 1시간 녹음이면 약 30분이라 이번 범위에서 제외. 그런 녹음은 Claude 후보 없이 턴 화면에서 직접 고친 뒤 "교정 완료"(D-R8). 재검토 시 job 에 `engine: claude | local` 만 추가하면 되는 구조로 둔다.

## 화면 구조 (IA)

### 사이드바 = 인박스

- 묶음 두 개: **처리할 것**(미정, 날짜 desc) / **끝난 것**(연결됨, 기본 접힘). 휴지통 메모에 연결된 녹음은 "끝난 것" 안에서 표시만.
- 행 = 녹음 시각 · 길이 / **전사 첫 문장 한 줄**(식별용, 서버가 목록에 포함) / 다음 할 일 회색 글자("인원 입력", "화자 나누는 중", "고칠 곳 12개", "연결 대기"). 상태를 색 알약 칩으로 표시하지 않는다(위치·세기·타이포).
- 행 앞 체크박스 → 선택 시 하단 "N개 삭제". "30초 미만 선택" 바로가기.
- "텍스트만"(m4a 없는 옛 결과) 은 처리할 것에 포함하되 ▶ 없음.

### 상세 = 작업대

```
녹음 시각 · 길이 · base                                    ⋯ (삭제 · 화자 다시 나누기)
▶ ━━━━━━━━━━━━━━━━━━━━━━  (고정, 스크롤해도 상단에 남음)

[다음 할 일 카드 — 상태별 하나]

참석자  ● 정진용교수님  ● 함창수  (이름 클릭 = 전체 변경)
─────────────────────────────────────────────
● 정진용교수님 01:10
  지금 뭐 어쩔 수 없지 지금은 일단 전투실험은 넘어갑시다 …
● 함창수 01:57
  네, 이게 매출화가 되어서 …   ← 클릭하면 그 자리에서 편집, 시각 클릭 = 그 지점 재생
```

다음 할 일 카드 (파이프라인 축 기준, 하나만):

| 상태 | 카드 |
|---|---|
| 전사 대기 | "자동 전사를 기다리는 중입니다" (액션 없음) |
| 초벌 전사 | 인원 수(필수) + 이름(선택) → [화자분리]. 예상 소요 시간 |
| 처리 중 | 단계 문구 한 줄. 다른 녹음으로 이동 가능 |
| 오류 | 원인 + [다시 실행] / [실패한 부분만 다시 실행] |
| 교정 중(화자분리 끝) | [Claude 로 고칠 곳 찾기](전사 전송 안내) · [교정 완료] |
| 리뷰 중(후보 있음) | "고칠 곳 N개 남음" + [다음 고칠 곳] · [교정 완료](남은 후보는 원문 유지) |
| 교정본 | 연결 후보 메모 2~3개 행(클릭 → 주의사항 확인 → 연결) · 다른 메모 찾기 · 새 메모로 만들기 |
| 연결됨 | "메모에 연결됨" + [메모 열기] |

연결·삭제 성공 시 처리할 것의 다음 녹음으로 자동 이동. 진입 시 처리할 것 맨 위 자동 선택(빈 상태 화면은 처리할 것이 0일 때만).

## 턴 화면 컴포넌트

- **파서(순수)** `src/lib/recordings/turns.ts`: 텍스트 → `{format, preamble, turns: [{time, speaker, text}], sections?}`. 지원 형식 두 가지, 실측:
  - 화자분리 형식(`merge.py`): `[mm:ss] 이름: 발화` 한 줄 한 턴, 빈 줄 구분.
  - 옛 사이드카 형식(18개, 예 `20260803_정진용교수님 미팅.transcript.md`): `mm:ss 이름` 줄 + 다음 줄부터 발화.
  - 메모 사이드카의 `## {시각} · {base}` 녹음 섹션 헤딩은 섹션 경계로 보존.
  - 어느 형식도 아니면 `format: "plain"` → 지금처럼 평문 표시·편집(textarea).
- **직렬화**: 읽은 형식 그대로 다시 쓴다(옛 형식 파일을 새 형식으로 바꾸지 않음). 파서→직렬화 왕복 무손실 테스트 필수.
- **컴포넌트** `TranscriptTurns`: 화자 색(기존 `--speaker-0..9`, 등장 순) · 이름 · 시각 · 발화. 발화 클릭 = 인라인 편집, 시각 클릭 = `onSeek(sec)`. 참석자 줄 이름 클릭 = 그 화자 전체 이름 변경. 교정 후보 하이라이트 슬롯(D-R7).
- **녹음 탭**: 작업 파일 = `화자분리.txt`(화자분리 후) 또는 `_audio/<base>.txt`(옛 교정본·텍스트만). 저장 = `PUT /api/recordings/:base/transcript`(debounce, mtime 충돌 검사).
- **메모 탭**: `MeetingForm` 의 기존 `docHistory`(transcript 칸)에 그대로 연결 → undo·저장·바뀐 칸만 저장(D5) 유지. 녹음 섹션마다 ▶ 와 녹음 탭 링크는 PR1 그대로.

## 서버 변경

- `GET /api/recordings` 행에 `firstLine`(작업 파일 첫 발화 60자) 추가.
- `PUT /api/recordings/:base/transcript {text, mtime}` — 작업 파일 저장. 연결된 녹음은 409(메모 쪽에서 편집).
- `POST /api/recordings/:base/complete` — 교정 완료: 작업 파일 → `_audio/<base>.txt`, 중간물(`diar.tsv`·`corrections*.json`·`anchored.json`·`normalize.log`·`화자분리.txt`) 정리. 이후 파이프라인 = 교정본.
- `POST /api/recordings/delete {bases}` — D-R4.
- link: 파이프라인이 교정본이 아니면 409 `notCorrected`. 원천은 `_audio/<base>.txt` 만(`tr.txt` 승격 경로 삭제).
- archive/unarchive 제거.
- 교정 후보 하이라이트용: `anchored.json` 항목을 턴에 매칭(같은 턴 텍스트 안 `hl[0]` 또는 `orig` 위치). 수락 = 작업 파일에서 그 구절 치환 후 저장, 결정 상태는 `.stt/<base>/review.json`.

## 범위 밖

- 단어장(glossary) 자동 성장, 화자 목소리 기억.
- 메모 쪽에서 녹음 섹션을 다른 메모로 옮기기(연결 해제 → 재연결은 기존 기능으로 가능).

## PR 분할 (제안)

한 PR(`feat/recording-redesign`)에서 커밋 단위로: ① 삭제 API·archive 제거·link 게이트 ② 턴 파서·직렬화 + `TranscriptTurns` + 메모 탭 교체 ③ 녹음 탭 IA(사이드바 인박스·다음 할 일 카드·자동 이동·작업 파일 편집·교정 완료) ④ 교정 후보 하이라이트 리뷰.

## Open Questions

- 메모 탭 턴 화면에서 녹음 섹션 헤딩(`## 시각 · base`)이 여러 개일 때 화면 구분 방식(섹션 제목 줄 vs 구분선).
- 턴 하나가 매우 길 때(whisper 가 끊지 않은 수 분짜리) 편집 UX.
