## Problem Statement

지금 앱은 Tauri 데스크탑 전용(V0.6 결정). 아이폰 설치가 번거롭고 무료 프로비저닝 재서명 때문에 주기적으로 재인증해야 한다. 메모앱 겸용이라 아무 때나 빠르게, 신호 0 오프라인(지하철·비행기)에서도 즉시 작성할 수 있어야 한다. → **앱을 웹앱 하나로 단일화**하고(Tauri 전면 제거), Pro 맥의 작은 로컬 서버가 정본 vault를 소유. **폰·air·Pro 모두 브라우저로 그 서버에 접속**해서 쓴다(폰은 PWA 홈화면 추가, 서명 0). 폰 오프라인은 **캡처 우선**(새 메모·편집을 outbox에 쌓아 서버로 밀기, 읽기는 최근 캐시). 이 골격은 캡틴이 이미 운영 중인 tower·growth와 동일하다(아래 "2차 개정").

## eng-review 방향 수정 (Approach B → capture-first)

초안은 "폰이 vault 전체를 IndexedDB에 복제(작으니까)"였는데, eng-review 외부 voice가 실제 `~/brain`을 측정해 전제를 반증했다. 확인된 사실:

- `~/brain` `.git` = 467MB, **loose object 2445개·pack 0 (gc 이력 없음)**, **iCloud Drive 안** → 서버가 자주 커밋하면 캡틴이 이미 데인 iCloud+git mtime-churn/부분sync 손상 함정 재현.
- `com.goodsoob.gbrain-sync` 데몬이 `~/brain`을 60초마다(working tree까지) 훑음 → 앱 서버 = **두 번째 writer** 충돌 표면.
- `notes/` = 456MB (앱이 **읽기만** 하는 브레인 노트). **앱이 쓰는 것**(portfolio 7.5M, meetings/journals/routines ≈0)은 아주 작음 → 무거운 건 "쓰기"가 아니라 "브레인 전체 오프라인 읽기". iOS Safari는 456MB 복제를 못 버티고 미사용 시 eviction으로 미sync 데이터까지 날림.

**수정된 방향 = capture-first.** 폰은 복제본을 안 든다. 오프라인 = 새 메모·편집을 로컬 outbox에 쌓기, 온라인 = 서버로 POST. 오프라인 읽기 = 최근 N개 캐시만, 과거 노트는 온라인 fetch. → iOS eviction 리스크를 outbox(작음)로 한정, 456MB 복제·양방향 sync·divergence 배지 대부분 제거. P1(빠른 폰 캡처)은 그대로 충족.

**선결조건 (2차 정의 → 3차 gc-only로 축소, 2026-09-18 완료):** ~~`.git`(467MB)만 iCloud 밖 로컬 분리~~ → **gc-only로 결정.** `.git` gc(loose 2445 → pack 1)만 실행하고 **`.git`은 iCloud에 유지**한다. 근거: iCloud+git 함정의 실질 pain은 loose object mtime-churn(iCloud가 감시하는 수천 개 작은 파일)인데, gc가 pack 1개로 압축해 그 churn을 해소한다. 부분sync 손상·동시 writer 충돌은 아직 미발생한 예방적 우려라, 이를 막으려 확정 편익(맥 간 git 히스토리 공유)을 포기하지 않는다 — 실제로 겪으면 그때 `.git`을 분리해도 늦지 않다(국소·되돌리기 가능). **잔여 리스크**: air fallback(T9) 중 Pro·air가 iCloud `.git`에 겹쳐 커밋하면 충돌 가능 → T9 설계에서 다룸. gbrain 데몬과 앱 서버 writer 관계 정리는 T2로 이관(현재 데몬이 단일 writer라 무해). 상세는 "2차 개정" 참조.

## What Makes This Cool

- 설치 = 홈화면 추가 한 번. Apple 서명·재인증 treadmill 완전 제거.
- 충돌을 "하나 선택"이 아니라 "전부 보존"으로 재정의 — 어떤 저장도 덮어쓰지 않고 시간순 히스토리로 쌓음. `~/brain`이 이미 git repo라 이 lossless 동작을 공짜로 얻고, sync 기반을 밑바닥부터 발명하지 않는다.
- 앱의 **파일 IO**는 이미 `VaultAdapter` 인터페이스(`src/lib/vault/adapter.ts:40-71`) 뒤로 캡슐화돼 있어 http 어댑터 추가로 대체 가능. 단 어댑터 밖 Tauri 탈출구(`gh`/`claude`/`curl`/`zip`/`asset://`/gcal)는 별도 서버 이전 필요 — "어댑터 하나면 끝"은 과장(eng-review 교정).

## Constraints

- 1인 본인 사용, 빌더 모드. over-engineering 회피 (multi-user·CRDT·복잡 권한 금지).
- 정본 vault = `~/brain` md 파일 (iCloud 공유, 로컬 git 복구 안전망). 이제 이것만 사용한다 (기존 iCloud md 폴더 병용 폐기).
- **앱은 웹앱 하나.** Tauri 전면 제거. 폰·air·Pro 모두 브라우저로 서버 접속. 네이티브 데스크탑 앱 없음. (tower·growth와 동일 골격)
- **맥 간 공유 = iCloud** (git remote 아님). Pro가 정본 서버·단일 writer. air는 Pro 다운 시에만 iCloud로 받은 brain에 대해 자기 로컬 서버를 단일 writer로 띄우는 fallback — Pro가 안 도니 동시 쓰기 충돌 없음.
- **폰 오프라인 = 캡처 우선.** 복제본 없음. 쓰기는 outbox, 읽기는 최근 캐시 + 온라인 fetch. 전체 브레인 오프라인 읽기는 비목표.
- data loss 절대 금지 (앱 제1원칙). 하드닝 예산은 **폰 outbox의 durability**(iOS eviction 방어)에 몰빵 — 여기가 실제 약한 고리.
- git은 서버(Pro/air 맥)에만 산다. 폰 브라우저는 git을 직접 돌리지 않는다.

## Premises

동의 완료:

- **P1** — 진짜 목표는 "PWA"가 아니라 "폰에서 마찰 0 즉시 메모"(설치 1회 · 재인증 제거 · 신호 0 작성). PWA는 수단.
- **P2** — 맥 vault = 정본은 유지·불가침. 정본은 이제 `~/brain`만.
- **P3** — 프로젝트의 위험·공수는 폰 오프라인 sync 레이어에 집중돼 있고, PWA 전환 자체(어댑터·서버 API)는 기계적이라 싸다.
- **P4** — PWA를 Tauri 2 Mobile보다 우선하는 결정적 이유 = Apple 서명/재인증 제거. Tauri mobile은 진짜 오프라인을 공짜로 주지만 재서명 treadmill을 그대로 짊어진다.

충돌 정책 (확정, 서버 측):
_capture-first에선 폰이 복제본을 안 들어 "같은 노트 동시 오프라인 편집"이 드물다. 그래도 폰이 최근 캐시에서 연 노트를 오프라인 편집하면 divergence는 가능 → 서버 측 lossless 규칙은 그대로 유지, divergence 배지 UI만 v1에서 미룬다(git에 다 남으므로 안전)._

- 어느 기기의 저장이든 = 불변 버전 하나가 시간순 히스토리에 쌓임 (기기·시각 태그).
- **"현재 노트" = 최신 버전 (LWW).** 진 버전도 죽지 않고 히스토리에 보존. **"최신" 판정 권위 = 서버 수신(커밋) 순서** — 폰 시계 드리프트로 오래된 오프라인 편집이 최신을 이기는 걸 막음. 폰 timestamp 는 표시용일 뿐 순서 판정에 안 씀.
- 충돌 = 아무것도 막지 않고 둘 다 버전으로 보존. 원하는 게 안 올라왔으면 히스토리에서 복구.
- backing store = `~/brain` git repo. 각 버전 = 커밋.
- **삭제·이름변경도 lossless.** 삭제 = tombstone 커밋(파일 제거하되 git 히스토리로 복구 가능). 오프라인 삭제 vs 다른 기기 편집 = 편집 버전이 살아 두 갈래로 남음. 이름변경(=제목변경=disk rename)은 경로 이동 커밋; 동시 rename+편집 = 두 경로에 두 버전. rename/delete 도 outbox op 로 모델링.
- **배지 신호** — 한 노트에 **divergent 버전**(git 상 서로 조상이 아닌 두 커밋 = 같은 부모에서 갈라짐)이 생기면 조용한 배지("다른 기기 버전 있음")로 히스토리 유도. 막지도 고르라고 강요도 안 함. 이 신호가 lossless 모델을 실제로 안전하게 만든다("덮인 걸 모르면 히스토리를 볼 생각도 안 한다"). (v1 비용 절감: divergent 는 어차피 git 에 다 남으므로 배지 UI 를 미루고 복구를 히스토리로만 시작해도 안전 — Open Questions 참조.)

## 어댑터 계약 변경 (write / watch / mtime)

기존 `VaultAdapter` 계약 중 3개는 백엔드 교체로 의미가 바뀐다. "어댑터 교체는 기계적"이라는 말은 read/list/write/delete/rename/exists/mkdir 에만 해당하고, 아래 셋은 각자 설계가 필요하다.

- **`write(relPath, content, expectedMtime?)` — 낙관적 잠금 은퇴.** 기존 Tauri 어댑터는 `expectedMtime` 불일치 시 `ConflictError` 를 던지고 데스크탑이 보존/덮어쓰기 모달을 띄웠다. lossless 모델에선 이 경로가 사라진다 — http/offline 어댑터는 `expectedMtime` 를 no-op 처리하고 절대 `ConflictError` 를 던지지 않는다(항상 새 버전으로 얹음). `ConflictError` 를 기대하던 호출부(데스크탑 충돌 모달)는 배지 신호 경로로 대체 — 제거 대상 목록을 해당 PR 에 명시.
- **`watch()` — 기계적 아님, 어댑터별 설계.** http 어댑터: 서버 SSE(재연결 로직 포함) → `VaultWatchEvent` 변환. offline 어댑터: outbox 적용 변경 + 서버에서 pull 한 커밋 **두 소스** 모두에서 발화. "SSE vs polling" 은 사소한 선택이 아니라 이 항목의 핵심.
- **`readMeta().mtime` — 어댑터별 소스 정의 필수.** 호출부가 정렬(date→time→mtime)·"최근 mtime 5개(이어서 쓸 노트)"에 쓴다. http=서버 git commit time, offline=IndexedDB 쓰기 시각. 표시·정렬용 mtime 과 순서 판정 권위(서버 수신 순서)를 분리하고, 호출부가 **어댑터 간** mtime 을 비교하지 않는지 확인(런타임엔 한 어댑터만 활성이라 안전하지만 기기 전환 정렬은 신경).

## 2차 개정: 웹앱 단일화 + 참조 아키텍처 (tower·growth)

캡틴이 "tower·growth랑 똑같이" 하라고 지정 → 아키텍처를 새로 발명하지 않고 이미 운영 중인 두 앱의 확립된 패턴을 따른다. 두 앱 실측 조사 결론:

**공통 골격 (= 채택):**
- 로컬 Node/Bun 서버 + **launchd** `RunAtLoad=true`+`KeepAlive=true` (로그인 시 자동 기동, 크래시 자동 재시작). plist 예: `com.goodsoob.growth.plist`(7060), `com.goodsoob.tower-personal.plist`(7071).
- **PWA** (manifest + service worker). 서버가 정적 빌드를 서빙(`express.static`/직접 서빙) + SPA fallback.
- 코드는 iCloud 안, 폰·외부는 브라우저로 접속. 네이티브 앱 없음.

**갈리는 지점과 우리 선택:**

| | growth | tower | **goodsoob-memory (채택)** |
|---|---|---|---|
| 외부 접속 | Tailscale | Cloudflare 터널 + CF Access | **Tailscale serve** (brain은 극도로 사적 → 공개 도메인 노출 X, tailnet 소속=인증) |
| 데이터 정본 | iCloud md 파일 | 로컬 SQLite | **iCloud brain md** (growth형) |
| 맥 간 공유 | iCloud 동기화 | 각 맥 독립 DB | **iCloud 동기화** (git remote 아님) |
| 오프라인 | IndexedDB 캐시 + 쓰기큐 + SW | Web Push | **capture outbox** (IndexedDB 쓰기큐, growth형) |
| git | 데이터 폴더 auto-commit **복구 안전망** | 코드만 | **brain git = 버전/복구 안전망** |

**goodsoob-memory ≈ growth** (md 데이터 + 오프라인 캡처). tower는 SQLite라 덜 가깝지만 launchd·PWA·터널 골격은 공유.

**확정 아키텍처:**
- **Pro 맥**: 정본 brain(iCloud) + Bun 서버(자기 포트, launchd 상주) + PWA 서빙. **단일 writer.** 폰·air·Pro 자신이 브라우저로 접속.
- **air 맥**: 평소엔 Pro 서버에 브라우저로 접속(자기 데이터 안 씀). **Pro 다운 시에만** iCloud로 받은 brain에 대해 자기 로컬 서버를 띄워 단일 writer로 fallback. Pro 복귀 시 iCloud가 md를 다시 일치시킴(Pro가 안 도는 동안 air만 썼으니 덮어쓰기 충돌 없음).
- **폰**: PWA capture-first. 오프라인 = outbox, Pro 다운 시 쌓아뒀다 복귀 시 flush(air로 라우팅 안 함, v1 범위 밖).
- **`.git` 위치** (3차 갱신, 2026-09-18): brain md working tree + **`.git` 모두 iCloud 공유**(맥 간 데이터·git 히스토리 일치). 무거운 loose churn만 gc(loose 2445 → pack 1)로 제거하고 `.git` 자체는 iCloud 유지. (2차의 "`.git`만 iCloud 밖 로컬, 히스토리 맥마다 독립"은 철회 — 근거는 선결조건 참조.)

**철회된 것 (앞선 논의에서 과설계로 판명):**
- ~~git remote push/pull로 맥 간 공유~~ → iCloud가 담당(두 참조 앱 모두 git remote 안 씀).
- ~~맥 간 append-only git merge / divergence 병합~~ → Pro 단일 writer라 불필요. (단 **한 노트 안의 버전 히스토리**를 git 커밋으로 보존하는 append-only 규칙은 유지 — "맥 간 merge"와 "커밋 버전 보존"은 별개. 폰이 오프라인 캐시에서 연 노트를 편집하는 드문 divergence만 대비.)

## 결정된 세부 (spec 리뷰 반영)

- **서버 노출·인증** — 서버는 tailscale 인터페이스에만 바인딩(절대 `0.0.0.0` 아님). 노출 = tailscale serve, 인증 = 네트워크 레벨(tailnet 소속)로 v1 처리 — 별도 앱 토큰 없음. `~/brain` 에 쓰는 엔드포인트가 1~2단계부터 unauthenticated 로 열리는 걸 방지.
- **커밋 granularity** — 매 keystroke·매 write 커밋 금지(=`~/brain` git log 오염). 앱은 **전용 subtree/브랜치**에 쓰고, **sync 경계에서 debounce 스쿼시**로 커밋. Next Step 2 의 "매 write 커밋"은 이 규칙으로 대체.
- **replica refresh vs dirty buffer** — 서버 커밋을 pull 해 복제본을 갱신할 때, **outbox 대기 항목이나 편집 중(dirty/focused) 버퍼가 있는 노트는 절대 덮지 않는다.** 들어온 버전은 replace 가 아니라 새 히스토리 버전으로 착지. (데스크탑에서 이미 고친 useMeeting list-loaded gate·watcher race 와 같은 계열 — Success Criteria 유실 0 의 실제 메커니즘.)

## Approaches Considered

### Approach A: 배관 먼저, 오프라인 2단계 (B에 흡수 — 단독 종착점 아님)
작은 Bun 서버 + `createHttpAdapter()` 직결, 폰 오프라인 복제를 다음 단계로 미루는 안. 단독으로는 캡틴이 못 박은 "신호 0 즉시 작성"을 v1에서 못 지켜 **종착점으로는 부적합**. 단, 이 순서 자체는 B의 1~3단계와 동일 — A는 버려진 게 아니라 B의 첫 국면으로 흡수된다. **실제로 거부된 유일한 안은 C.**

### Approach B: 폰이 full 복제본을 든 완전 오프라인 (ruled out — eng-review)
서버는 `~/brain` git 소유, 폰은 vault 전체를 IndexedDB에 복제 + outbox + 서비스워커, 양방향 sync. → **탈락.** 전제("작으니 full 복제")가 실측 반증(브레인 읽기 456MB) + iOS eviction/456MB 복제 불가. "eng-review 방향 수정" 참조.

### Approach C: git을 폰까지 (ruled out)
폰 브라우저가 진짜 git repo(isomorphic-git + OPFS), 서버에 push/pull. → 브라우저-git 신기술 위험, lossless가 이미 싸게 주는 걸 비싸게 삼. 탈락.

### Approach D: capture-first (chosen)
폰은 복제본 없음. 오프라인 = 새 메모·편집을 로컬 outbox에 append, 온라인 = 서버로 POST → 서버가 `~/brain` git 커밋. 오프라인 읽기 = 최근 N개 캐시, 과거는 온라인 fetch. 데스크탑은 Tauri 유지. 서버는 폰 전용 + `gh`/`claude`/asset 서빙 엔드포인트.

## Recommended Approach

**D (capture-first).** P1(빠른 폰 캡처, 신호 0)을 실제로 충족하면서, B가 안고 온 위험(iOS eviction·456MB 복제)을 구조적으로 제거한다. 캡처는 작아서 outbox durability만 방어하면 되고, 무거운 "브레인 전체 오프라인 읽기"는 비목표로 잘라낸다. 서버 측 git append-only(lossless) 규칙은 유지 — 편집이 서버에 닿는 순간부터는 아무것도 안 잃는다. (데스크탑 SPOF 우려는 2차 개정에서 "air 로컬 서버 fallback"으로 해소.)

부가 결정: **서버는 독립 프로세스** (자기 포트 + 자기 launchd plist). tower(7071)에 얹지 않는다 — growth(7060)·tower(7071)처럼 프로젝트마다 독립 launchd가 캡틴의 확립된 패턴.

1. **outbox 미flush 중 iOS eviction → 메모 유실.** 테스트 필요(step 8) · persist+미sync 표시 · **표시 없으면 critical gap.**
